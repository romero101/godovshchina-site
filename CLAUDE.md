# Годовщина — правила работы с репозиторием

Сайт polis-godovshchina.ru. Push в `main` = автоматическая выкладка на живой сайт (GitHub Pages), поэтому:

## Правило 1. Изменил функционал — обнови тест-кейсы
После любого изменения поведения (калькулятор, форма партнёра, ссылки, аналитика, страницы, бэкенд) в том же коммите обновляются:
- `docs/test-cases.html` — единственный источник кейсов (массивы `SECTIONS`, `ENVS`, `KEY`); из него публикуется чек-лист
  «Тест-кейсы Годовщины» (`Artifact` с `url` https://claude.ai/code/artifact/38827053-dcde-4aa5-a784-9901ac4c214a) и
  генерируется `docs/test-cases.md` командой `node tools/gen_testcases.mjs`;
- `tests/e2e/run.mjs` — автотесты, если кейс автоматизируем.
У кейса есть приоритет (К/В/Ж), режим (авто/руками) и «когда» (релиз/месяц/разово). Не плодить кейсы: один кейс = одно
поведение, у которого есть измеримый результат; мониторинг (сверки, запросы Директа, кабинет партнёра) в кейсы не входит.

## Правило 2. Перед выкладкой — критические кейсы
Выкладка только через `tools/release.sh`: локальная сборка → `MODE=release` (все авто-кейсы «релиз» на 3 окружениях) →
при упавших критических выкладка отменяется → `git push` → ожидание, пока GitHub Pages отдаст новую страницу →
`MODE=smoke` на живом сайте. Ручные критические (3.3 приложение Яндекс, 3.7 оформление у партнёра) просить Романа
пройти до выкладки, только если менялся путь до партнёра. В отчёте Роману писать: «критические кейсы прошли: N из N».
Результаты прогона (`tests/e2e/db-results-*.json`) записывать в базу чек-листа через `write_db` с `db_op: update`
(документ `tests/results`), чтобы не затирать ручные отметки. Раз в месяц: `MODE=monthly node tests/e2e/run.mjs`
(PageSpeed, скорость и цены Полис812, калибровка калькулятора) и ручной ряд «месяц» у Романа.

## Правило 3. Версия тест-кейсов
Каждое изменение набора кейсов поднимает версию в заголовке `docs/test-cases.html` и добавляет запись в «Историю версий»
с комментарием, что и почему изменилось. Затем перегенерировать md и переопубликовать чек-лист.

## Версии кода
- Стабильные состояния помечаются тегами `vX.Y` с описанием. `v1.0` — день запуска Директа, 6 сентября 2026.
- Номера в адресах ассетов (`calc.js?v=N`, `style.css?v=N`, `metrika.js?v=N`) поднимать при каждом изменении файла;
  константы в `tools/gen_banks.py`, страницы правятся заменой по всем HTML.
