# Годовщина — правила работы с репозиторием

Сайт polis-godovshchina.ru. Push в `main` = автоматическая выкладка на живой сайт (GitHub Pages), поэтому:

## Правило 1. Изменил функционал — обнови тест-кейсы
После любого изменения поведения (калькулятор, форма партнёра, ссылки, аналитика, страницы, бэкенд) в том же коммите обновляются:
- `docs/test-cases.md` — текст кейсов;
- чек-лист «Тест-кейсы Годовщины» (артефакт, синхронизируется с Романом): https://claude.ai/code/artifact/38827053-dcde-4aa5-a784-9901ac4c214a — те же кейсы с чекбоксами;
- `tests/e2e/run.mjs` — автотесты, если кейс автоматизируем.

Источник тест-кейсов — `docs/test-cases.html` (данные в массиве SECTIONS); из него же публикуется артефакт (`Artifact` с url чек-листа) и генерируется `docs/test-cases.md`. При каждом изменении кейсов: поднять номер версии в заголовке и добавить запись в «Историю версий» с комментарием, что и почему изменилось.

## Правило 2. Перед выкладкой — критические кейсы
Перед push в `main` прогоняются все кейсы с приоритетом «К» (критично). Автоматизируемые:

```bash
cd tests/e2e && node run.mjs
```

Ручные критические (приложение Яндекс, оплата у партнёра, кабинет Полис812) — попросить Романа пройти по чек-листу.
Выкладка только после зелёных критических кейсов. В отчёте Роману писать: «критические кейсы прошли: N из N».

## Версии
- Стабильные состояния помечаются тегами `vX.Y` с описанием. `v1.0` — день запуска Директа, 6 сентября 2026.
- Номера в адресах ассетов (`calc.js?v=N`, `style.css?v=N`, `metrika.js?v=N`) поднимать при каждом изменении файла; константы в `tools/gen_banks.py`, страницы правятся заменой по всем HTML.
